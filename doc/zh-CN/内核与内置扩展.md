# 内核与内置扩展边界

Cilexec 始终发布为单一二进制文件。系统不支持外部 JAR、运行时插件、动态
ClassLoader 或可安装内核扩展。

源码分为四个边界：

```text
com.follarce.kernel.api          内核与内置扩展之间的稳定契约
com.follarce.kernel              内核注册、分派与运行实现
com.follarce.extension.builtin   编译进二进制文件的内置 FCL Provider
com.follarce.bootstrap           唯一允许装配具体内置扩展的位置
```

依赖方向固定为：

```text
bootstrap -> kernel
bootstrap -> extension.builtin
kernel -> kernel.api
extension.builtin -> kernel.api
```

内核不能依赖具体 Provider。Provider 列表由 `BuiltinProviderIndex` 在编译时明确
装配，不扫描 classpath，也不存在 `META-INF/services` 扩展入口。

新增 FCL 原生 namespace 时，必须把实现加入源码和 `BuiltinProviderIndex`，经过
测试后随整个 Cilexec JAR 一起发布。普通软件包只能包含 FCL、资源和数据。
